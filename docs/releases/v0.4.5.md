## 0. About this release

v0.4.5 lets the assistant (`erp_assist`, the MCP adapter and the staff chat
that uses the same tools) create every document. Until now it could read and
edit them, but it could not make a sales order from scratch, an invoice for
work that had no order, or a purchase order, and it could not turn a quote
into an order. The REST API already accepted all of that; the tools were
missing. It also lets a restricted service account use the document actions
those tools call. It is v0.4.4 plus these two changes:

- **New tools.** `create_order`, `create_order_line`, `delete_order_line`,
  `create_invoice`, `list_invoices`, `get_invoice`, `update_invoice`,
  `convert_quote_to_order`, `create_quote_line`, `delete_quote_line`,
  `create_purchase_order`, `create_po_line`, `delete_po_line`,
  `add_party_email`, `add_party_phone`, `list_party_relationships` and
  `create_party_relationship`.
- **A service account's contract can cover custom actions.** Until now every
  writing `@action` (`recalculate`, `transition`, `duplicate`, the two
  conversions) was refused for every service account, whatever its role
  held. A viewset now names the model permissions that describe each action,
  and a service role holding all of them may call it. See section 1.
- **Purchase-order numbers are assigned by the server** when an API caller
  omits `po_number`, as order and quote numbers already were.
- **`create_quote` works for a caller with no company of its own** (the
  legacy API key) and no longer leaves an empty quote when a line is invalid.

No migration, no new settings and no new required secrets. The dependency
ranges are those of v0.4.4 (Django 6.0, mcp 1). Install with
`pip install fincas==0.4.5`; the import name stays `golden_erp`.

## 1. Before you upgrade

Upgrading from v0.4.4: install the new version. There is nothing to migrate.
A deployment that runs the MCP adapter as its own process
(`python -m erp_assist.mcp_adapter`) restarts it to get the new tools.

**Check your service roles before you upgrade.** A `kind="service"` role in
`GOLDEN_ROLES` gains the custom actions that its existing permissions
describe, with no change to the role:

| The role holds | It gains |
|---|---|
| `orders.change_order` | `transition` and `recalculate` on orders |
| `orders.change_quote` | `transition` and `recalculate` on quotes |
| `orders.view_order` + `orders.add_order` | `duplicate` on orders (same pattern for quotes and purchase orders) |
| `purchasing.change_purchaseorder` | `transition` and `recalculate` on purchase orders |
| `orders.change_suborder` + `orders.change_order` | `transition` on sub-orders |
| `fulfillment.change_pickticket` | `transition` on pick tickets |
| `orders.change_salesinvoice` | `recalculate` on invoices |
| `orders.change_quote`, `orders.add_order`, `orders.view_order`, `crm.change_engagement` | `convert-to-order` |
| `orders.view_order`, `orders.change_order`, `orders.add_salesinvoice`, `orders.view_salesinvoice`, `payments.change_payment` | `convert-to-invoice` |

A status change made this way emits the document's lifecycle signals and
webhooks, as it does for staff. If a role should not gain an action, remove
the permission from it before upgrading. `send-confirmation`, a purchase
order's `receive` and the CRM actions stay refused for every service account.

From v0.4.3 or earlier, follow the v0.4.4 notes first
([docs/releases/v0.4.4.md](v0.4.4.md) section 1).

## 2. Behavior changes staff will notice

- Nothing changes for staff from the service-account change.
- The chat assistant can create a sales order, an invoice, a purchase order
  and quote lines when asked, and can convert a quote to an order.
- An order or quote line the assistant adds may be free-form (freight, a
  service, a one-off): it names no catalog item and carries the SKU `MISC`
  unless one is given. A purchase-order line always names a catalog item.
- An invoice the assistant creates is a **draft**. It is not sent and not
  posted to the ledger until its status leaves draft.

## 3. Known limitations

- **A restricted service account needs the permissions in section 1** to use
  the tools that call a custom action: `create_order` (when it has lines),
  `create_invoice`, `convert_quote_to_order` and the line tools call
  `recalculate`, `convert-to-invoice` or `convert-to-order`. The line tools
  also need `add_` / `delete_` on the line model.
- `convert-to-order` and `convert-to-invoice` do not check the source
  document's status: a canceled quote or order can still be converted, by
  staff as well as by a service account.
- There is no standalone invoice: `create_invoice` creates the order too.
- There is no free-form purchase-order line.
- The invoice email still goes to the customer's one address, with no cc.
- The limitations in the v0.4.4 notes still apply
  ([docs/releases/v0.4.4.md](v0.4.4.md) section 3).
