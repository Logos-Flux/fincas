## 0. About this release

v0.4.2 makes the storefront's checkout land in the back office whole: a
guest order now arrives with its cart lines, priced by the server from the
catalog, and a retried checkout returns the order it already placed instead
of creating a second one. It also fixes the `order.placed` webhook's total,
and brings dependency updates, a richer demo seed and the release tooling for
releases built on top of public `main`.

No migrations and no new required secrets. Install with
`pip install fincas==0.4.2`; the import name stays `golden_erp`.

## 1. Before you upgrade

Upgrading from v0.4.1:

1. **If you set `CORS_ALLOW_HEADERS` yourself**, add `idempotency-key` to it
   (golden's own default includes it). Without it the browser's preflight
   fails and no cross-origin checkout can be placed; `manage.py check` warns
   with `core.W115`.
2. **Behind a proxy, set `TRUSTED_PROXIES`.** Guest checkout is now
   rate-limited per client IP (`GOLDEN_GUEST_ORDER_RATE`, default
   `10/minute`); without `TRUSTED_PROXIES` every shopper shares the proxy's
   bucket (`core.W114` already warns).
3. **Custom storefronts** (anything other than the bundled `storefront/`):
   - a guest checkout must send `lines: [{"variant": <id>, "quantity": <int>}]`;
     without them it is refused (`lines_required`), and the old `items` key is
     ignored;
   - the guest response is a narrow confirmation (`order_number`, `lines`,
     totals, `total_amount`), not the staff order payload;
   - `Idempotency-Key` is now honored: 16-200 characters of `A-Za-z0-9._:-`,
     one random key per checkout. Reusing a key for a different checkout
     within 24 hours is refused (409 `idempotency_key_reused`).
4. **Webhook consumers:** `order.placed` `total_amount` now carries the
   order's total instead of `"0.00"`. If you worked around the zero, remove
   the workaround.
5. `manage.py migrate` applies nothing (no new migrations).

## 2. Behavior changes staff will notice

- Storefront orders arrive with their lines, in one "Shipment 1" group,
  priced from each variant's public price. They carry no tax and no shipping:
  add both in the order editor, as before.
- Stock is checked at checkout but not reserved; commit it through the usual
  back-office flow.
- A storefront order's **External ID** (Source panel) holds
  `storefront:<hash>`: that is what stops a retried checkout from creating a
  duplicate. Don't edit it.
- `manage.py seed_demo_commerce` builds a full demo catalog with 90 days of
  orders, invoices and purchasing on top of `seed_demo_data`.

## 3. Known limitations

- Guest orders get no tax or shipping, and price lists, quantity breaks and
  coupons are not applied at checkout (the coupon code is recorded for
  staff). Variant ordering rules (minimum quantity, pallet-only, unit
  multiples) are not enforced on guest orders yet.
- The duplicate-order guard is guaranteed on Postgres under READ COMMITTED
  (the default). On SQLite, two simultaneous submits with one key can still
  both create an order. A database-enforced key table is planned.
- `order.placed` for an order created header-first through the staff API is
  emitted on that first save, before lines exist, so its `total_amount` is
  the header's (usually `0.00`). Guest checkout emits after pricing.
